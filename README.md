# Арда: Дашбоард по Средиземью

Учебный проект на HTML, CSS и JavaScript ES-модулях для практической работы № 2 по WEB

## Возможности
- Тематическая панель с видео в hero-блоке;
- динамическое добавление, сворачивание и удаление карточек;
- базовый класс `UIComponent` и классы-наследники;
- виджеты The One API: персонажи, цитаты, книги, фильмы и главы (для них пользователь вручную вводит токен);
- два дополнительных API без ключа: Potter DB и Open Library;
- состояния загрузки, пустого результата и ошибки с возможностью повторить запрос;
- задачи и состав панели сохраняются в `localStorage`, после обновления страницы восстанавливаются;
- токен The One API не записывается в файлы проекта или `localStorage`.

## Источники API
1. The One API: https://the-one-api.dev/documentation — дополнительный архив Средиземья; требуется токен пользователя.
2. Potter DB: https://docs.potterdb.com/apis/rest — публичный API о персонажах, книгах и магии Гарри Поттера; ключ не нужен.
3. Open Library: https://openlibrary.org/developers/api — открытый книжный каталог; ключ не нужен.

## Структура
- `index.html` — разметка страницы, приветственный блок и дополнительные API-разделы;
- `main.js` — инициализация панели и публичных API;
- `js/UIComponent.js` — базовый класс, общие кнопки и очистка обработчиков;
- `js/Dashboard.js` — реестр виджетов, управление и сохранение состояния;
- `js/CharacterWidget.js` — персонажи The One API;
- `js/QuoteWidget.js` — цитаты The One API;
- `js/BookShelfWidget.js` — книги The One API;
- `js/MovieWidget.js` — фильмы The One API;
- `js/ChapterWidget.js` — главы The One API;
- `js/ToDoWidget.js` — список задач/заметок;
- `js/lotrApi.js` — запросы к The One API;
- `styles/main.css` — оформление страницы;
- `styles/components.css` — оформление виджетов;
- `assets/video/` — видео для hero-блока;
- `assets/fonts/` — локальный шрифт проекта.

## Ограничения и безопасность
- Не добавлять API-токены в исходники, README, Git-репозиторий или открытые документы.
- Токен The One API вводится вручную в поле страницы и хранится только в памяти вкладки; после обновления страницы его нужно ввести заново. Любой токен, используемый непосредственно из браузера, может быть виден в инструментах разработчика и сетевых запросах.
- Если токен когда-либо попал в публичный репозиторий или был передан в архив, отзовите его/создайте новый в личном кабинете сервиса, если такая функция доступна.
- Состояние панели сохраняется в браузере. Если `localStorage` недоступен, панель продолжает работать, но сохранение может не сработать.
- Внешние API зависят от доступности сети и самих сервисов. При сетевой ошибке показывается сообщение и кнопка повтора.
- Данные API выводятся через DOM-элементы и `textContent`, а не вставляются через `innerHTML`.

## Журнал применения ИИ

### Планирование структуры проекта

**Суть запроса:**
> Проанализируй требования работы по интерактивной панели на HTML, CSS и JavaScript. Предложи простую архитектуру на ES-модулях с базовым классом UIComponent и отдельными классами виджетов. Объясни назначение каждого файла, а также расскажи про возможность и особенности добавления видео-материала.

**Содержание ответа (ключевые моменты):**
- Вынести общую логику виджетов в базовый класс, например создание DOM-элементов и очистку обработчиков.
- Сделать отдельный класс для каждого типа карточки, а управление их добавлением и удалением поручить классу панели.
- Хранить разметку в `index.html`, стили в CSS-файлах, а логику виджетов и API в отдельных JS-модулях.
- Видео для hero-блока хранить локально в `assets/video/` и подключать тегом `<video>` с атрибутами `muted`, `loop` и `autoplay`, чтобы фоновое видео воспроизводилось без звука и не мешало работе страницы.

### Обработка данных внешнего API

**Суть запроса:**
> Покажи, как безопасно обработать запрос к публичному REST API в браузерном JavaScript: состояния загрузки, пустого ответа и ошибки, кнопку повторного запроса и вывод текста через textContent, без вставки ответа через innerHTML.

**Содержание ответа (ключевые моменты):**
- Выполнять запрос через `fetch` и проверять `response.ok` перед разбором JSON.
- Показывать пользователю состояния загрузки, отсутствия данных и ошибки, оставляя возможность повторить запрос.
- Вставлять текст внешнего API через `textContent` и создавать нужные элементы DOM отдельно.

### Проверка требований перед сдачей

**Суть запроса:**
> Составь чек-лист для проверки учебной панели: сохранение задач и состава виджетов в localStorage, восстановление после перезагрузки, независимая работа двух API, доступность кнопок с клавиатуры и понятные сообщения об ошибках.

**Содержание ответа (ключевые моменты):**
- Добавить задачу, обновить страницу и проверить, сохранилась ли она.
- Проверить каждый внешний API отдельно и убедиться, что ошибка одного источника не мешает работе другого.
- Пройтись по кнопкам клавиатурой и проверить видимый индикатор фокуса.
- Отключить сеть или вызвать ошибку запроса и проверить, появляется ли понятное сообщение.
